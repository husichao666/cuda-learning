# 实验记录约定

每个算子把可复现的结论与对应代码放在一起。正确性通过和性能改善分别记录，未执行的检查明确标注。

## 记录模板

| 项目 | 内容 |
| --- | --- |
| 代码 | 文件、版本或提交，完整编译与运行命令 |
| 环境 | GPU、驱动、CUDA、编译器；使用框架时再记录框架版本 |
| 执行方式 | 真实 GPU、功能模拟或其他后端，是否使用 CUDA Graph |
| 输入 | shape、dtype、stride、数值范围、随机种子 |
| 接口 | 输入输出、空输入策略、支持与不支持的布局 |
| 正确性 | reference、误差与容差依据、边界用例、内存检查结果 |
| 性能 | 起止边界、是否包含分配和传输、预热、重复次数、中位数与波动 |
| 解释 | 优化假设、有效与退化形状、尚未验证的情况 |

## 目录与文件

算子目录中保留 README、源码及必要的 `validation/` 记录。精简日志可以采用 JSON 或文本格式；大规模 profiler 输出放在本地忽略目录，提交分析结论和复现命令。

第一周的记录示例见 [vector_add/validation](../operators/cuda/vector_add/validation/README.md)。现有 FUNCTIONAL 日志证明相应示例在该模式下可运行，不代表已验证真实 GPU 的吞吐、带宽或延迟。

## 测量边界

Kernel 区间、forward + backward、完整调用和训练 step 分开记录。连续重复执行同一份数据时注明缓存条件；CUDA events 包围的区间也可能包含提交空档。性能比较固定 shape、dtype、数值语义和计时方式，保留变慢的例子。
